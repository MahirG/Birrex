# BirrEX Voice Studio — local upstream connector
This integration uses the actual VoiceStudio OpenAI-compatible API, not a copied AI engine. Upstream https://github.com/debpalash/VoiceStudio (AGPL-3.0); no upstream source is modified or bundled. Review upstream/model license and commercial use requirements independently.
1. Install upstream using https://voicestudio.sh/ on a supported computer (upstream documents 8 GB RAM and 10 GB disk minimum). Start its local backend on 127.0.0.1:3900.
2. Clone the BirrEX branch and install Node.js 22. From the repository root run `node exchange/scripts/voice-bridge.mjs`.
3. Open http://127.0.0.1:3910/voice-studio on that same computer. Generate English narration using the upstream default voice. Browser preview is separate and uses browser/OS voices; Amharic and Afaan Oromo require actual engine/device validation.
Bridge is loopback-only, checks Host and Origin, uses a fixed upstream and two allowlisted API paths, rejects cross-origin POSTs, bounds requests/audio/concurrency, and never stores scripts or tokens. Do not expose either port publicly. No remote compute, AI cloning, or video dubbing is provisioned. A mobile-accessible hosted service needs separately approved compute and access controls. Run `node exchange/scripts/test-voice.mjs` for mocked API checks. Actual provider inference remains unverified.

## Private host deployment and genuine inference acceptance
The upstream recommended production image (0.5.6) is pinned in `exchange/voice-compose.yml`, with persistent local models and data. Reference: https://github.com/debpalash/VoiceStudio/blob/main/docs/production-private-api.md . This is deployment configuration, not a running service.
- On an adequately resourced approved Linux/Windows Docker host, set OMNIVOICE_API_KEY in the terminal environment (use a password manager; never commit the secret), then run `docker compose -f exchange/voice-compose.yml up -d`.
- On that host open http://127.0.0.1:3900, authenticate and choose/install a model after reviewing the model's license and storage requirements. Wait for its download and warm-up to complete. Set BIRREX_VOICE_MODEL to the installed engine ID (optional, default tts-1 uses the active engine). The bridge forwards the key to the local engine only; no root key reaches a browser. The bridge uses the upstream alloy alias and validates actual WAV chunks.
- With the same env configured and port 3910 free, run `node exchange/scripts/verify-voice-live.mjs birrex-check.wav`. This sends an actual test narration through the bridge, validates the returned audio container and duration, logs measured latency and saves the audio to a new file. Listen to the sample before declaring voice quality accepted.
- Run `node exchange/scripts/voice-bridge.mjs` for interactive use on the host. Do not expose 3900 or 3910 directly to the Internet. A hosted mobile service needs an approved private host and authenticated service boundary; this configuration does not enable one.
